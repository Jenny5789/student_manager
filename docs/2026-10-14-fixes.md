# 기능 수정 및 검증 기록 — 2026-10-14

Student Manager의 입력·검색 오류를 실제 코드와 테스트용 SQLite DB로 확인하고 수정했다. 이번 기록은 소스 코드 수정에 대한 결과이며, 기존 `dist/` 실행 파일의 검증 결과는 아니다.

## 1. 학생 추가: 미선택 입력 차단

- **문제:** 이름만 입력하고 학년·반을 선택하지 않아도 학생이 추가됐다. 미선택 값 `0`을 DB 저장 전에 검사하지 않았다.
- **변경 이유:** 학년·반·번호를 선택한 학생만 저장하도록 UI 입력 단계에서 잘못된 요청을 차단해야 했다.
- **수정 내용:** `views/student_tab.py`의 `_add_student()`에 학년·반과 번호의 미선택 검사를 추가했다. 잘못된 입력에는 안내를 표시하고 `return`하여 `db.add_student()` 호출을 막는다. 추가 가능한 번호가 없는 경우의 기존 검사도 유지했다.
- **검증 결과:** 학년·반 미선택 입력은 저장되지 않았고, 정상 입력은 저장 후 조회됐다.

| 조건 | 기대 결과 | 실제 결과 | 확인 상태 |
| --- | --- | --- | --- |
| 이름 입력, 학년·반 미선택 | 안내 후 추가 차단 | 학생 수 유지, 안내 확인 | 확인 완료 |
| 학년만 선택 / 반만 선택 | 안내 후 추가 차단 | 각각 학생 수 유지, 안내 확인 | 확인 완료 |
| 이름에 공백만 입력 | 기존 이름 검사로 추가 차단 | 학생 수 유지, 이름 입력 안내 확인 | 확인 완료 |
| 이름·학년·반·사용 가능한 번호 입력 | 학생 저장 및 조회 | 학생 수 1명 증가, 해당 키와 이름 조회 성공 | 확인 완료 |
| 반의 1~40번을 모두 사용 | 추가 차단 | 학생 수 유지, 사용 가능한 번호가 없다는 안내 확인 | 확인 완료 |

번호 값 `0`을 차단하는 코드도 추가했으나, 해당 분기만을 독립적으로 실행하는 테스트는 아직 하지 않았다. DB 계층이나 테이블 제약조건은 이번에 수정하지 않았다.

## 2. 성적 관리: 학년·반·번호 검색 수정

- **문제:** 학년 드롭다운에 표시 문자열만 등록하여 `currentData()`가 `None`을 반환했다. 번호 목록은 `currentIndex() + 1`로 학년을 계산해 선택한 학년보다 한 학년 뒤의 번호를 조회했다. 검색 버튼과 Enter 입력은 이름 검색에만 연결되어 이름이 비어 있으면 조건 검색을 실행하지 않았다.
- **변경 이유:** UI의 선택값과 DB 조회 조건이 일치하고, 이름을 입력하지 않아도 학년·반·번호로 검색할 수 있어야 했다.
- **수정 내용:** `views/score_tab.py`에서 각 학년에 정수 데이터 `1`, `2`, `3`을 등록했다. 번호 조회에도 `currentData()`를 사용한다. 이름이 비어 있으면 `_load_students()`로 조건 검색을 실행한다. 학년 없이 반만 선택한 경우 학년 선택 안내를 표시하고 조회를 중단한다.
- **검증 결과:** 서로 다른 학년·반·번호의 테스트 학생 5명을 저장한 DB에서 검색 버튼을 호출하고 테이블의 학생 키 `(학년, 반, 번호)`를 기대값과 비교했다.

| 조건 | 기대 결과 | 실제 결과 | 확인 상태 |
| --- | --- | --- | --- |
| 이름·선택 조건 없음 | 전체 학생 조회 | 테스트 학생 5명과 일치 | 확인 완료 |
| 1학년 선택 | 1학년 학생만 조회 | 해당 학생 3명과 일치 | 확인 완료 |
| 1학년 1반 선택 | 해당 반 학생과 번호 목록 표시 | 학생 2명, 번호 목록 `[2, 7]`과 일치 | 확인 완료 |
| 1학년 1반 7번 선택 | 특정 학생만 조회 | 해당 키 1명과 일치 | 확인 완료 |
| 학년을 2학년으로 변경 | 반·번호 초기화 | 반 미선택 상태, 번호 기본 항목으로 초기화 | 확인 완료 |
| 2학년 1반 / 3학년 1반 | 각 학년의 번호 및 학생 조회 | 각각 번호 `9`, `12`와 학생 조회 결과 일치 | 확인 완료 |
| 학생 없는 반 선택 | 빈 번호 목록과 조회 결과 | 기본 번호 항목만 유지, 조회 0명 | 확인 완료 |
| 이름과 선택 조건을 함께 입력 | 기존 동작대로 이름 검색 우선 | 이름에 해당하는 학생 조회 | 확인 완료 |
| 학년 미선택, 반만 선택 | 안내 후 조회 중단 | 안내 확인, 기존 테이블 유지 | 확인 완료 |

드롭다운 갱신 후 신호 차단이 해제되는 것도 확인했다. Enter 키 입력 자체는 이번 자동 점검에서 재현하지 않았다.

## 3. 검증 환경과 데이터 보존

- 실행 환경: Windows, Python 3.12.12. 기존 `venv/Lib/site-packages`의 PyQt5를 연결해 테스트했다.
- 기존 `venv`의 Python 실행 파일은 다른 PC의 경로를 참조하여 실행되지 않았다. 가상환경 자체를 복구한 상태는 아니다.
- Qt 플랫폼 플러그인 경로를 명시하고 `QT_QPA_PLATFORM=offscreen`으로 화면 표시 없이 위젯과 처리 함수를 실행했다.
- 안내창은 자동 응답으로 대체했다. 실제 마우스 클릭, 안내창 배치, 사용자가 보는 화면 상태는 검증하지 않았다.
- 별도 테스트 DB를 사용했다. 학생 추가 테스트는 실제 추가 처리 함수를 호출했고, 성적 검색 테스트는 Qt 검색 버튼의 `click()`을 호출했다.
- 기존 `database/student.db`의 SHA-256은 최초 확인값과 일치했다: `3E427F7B046EA4F675C7AB9AED6CA750240CD99C04E4229F1C7F33252CDF42BE`.
- 수정한 두 Python 파일에 대한 `git diff --check`를 통과했다. 기존 README 변경은 이번 작업에 포함하지 않았다.

## 4. 성적 수정·일괄 저장 및 정렬

### 문제

수정 전 자동 테스트 6개에서 다음 문제를 재현했다.

- 정상 점수와 잘못된 점수가 섞이면 정상 학생의 성적이 먼저 저장됐다.
- 수정 후 다른 학생을 검색하면 화면 밖 학생의 변경은 저장되지 않았지만 수정 목록은 지워졌다.
- 전체 보기를 다시 호출하면 저장 전 점수가 화면에서 사라졌다.
- 저장 성공 후 강조 해제가 다시 변경 신호를 발생시켜 굵은 글씨가 남았다.
- 학생 삭제 이후 성적 저장을 시도해도 다른 학생이 먼저 저장되고 저장 성공 안내가 표시됐다.
- 점수 정렬이 문자열 비교여서 오름차순에서 `80`이 `9`보다 앞에 배치됐다.

### 변경 이유 및 수정 내용

검색 결과와 저장 대상을 분리하여 조회를 바꾸어도 저장 전 변경을 유지하고, 일괄 저장의 성공·실패가 명확하도록 처리했다.

- `views/score_tab.py`: 학생 키별 수정 내용을 조회 테이블에 다시 반영한다. 일괄 저장은 화면 밖 학생을 포함한 수정 목록 전체를 검증한다. 잘못된 입력의 평균에는 `입력 확인`을 표시한다.
- `database/db_manager.py`: `update_scores_batch()`를 추가했다. `BEGIN IMMEDIATE`와 하나의 트랜잭션으로 수정된 과목만 반영하고 평균을 계산한다. 학생이 없거나 점수가 잘못되면 예외를 발생시켜 전체 변경을 롤백한다. 연결은 `finally`에서 닫는다.
- 저장 오류 시 수정 목록을 유지하고 안내한다. 성공 시에만 목록을 비우고 표시 중인 학생을 DB에서 다시 조회하여 강조를 해제한다. 비고의 즉시 저장은 성적 일괄 저장과 별도로 유지한다.
- 셀 꾸밈과 평균 표시를 바꾸는 동안 변경 신호를 차단하여 해당 변경이 다시 성적 수정 처리로 들어오지 않게 했다.
- 숫자로 비교하는 `ScoreItem`을 추가하여 과목 점수와 평균을 숫자 순서로 정렬한다.

일반 실행 환경을 구성한 뒤 아래 명령으로 테스트를 다시 실행할 수 있다. 이번 실행에서는 기존 가상환경 라이브러리 경로 및 Qt 플러그인 경로를 별도로 지정했다.

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
python -m unittest discover -s tests -v
```

검증 한계: DB 잠금 오류는 예외를 주입해 처리 흐름만 확인했다. 실제 프로세스 간 잠금과 창 닫기 시 미저장 데이터 처리는 확인하지 않았다. 새 DBManager를 통한 재조회는 앱 종료·재실행 또는 다른 PC 검증을 대체하지 않는다.
